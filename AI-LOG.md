* получать список запусков через `GET http://localhost:3001/runs`;

### Ручные правки и проверка
* **Статус:** Доработано
* **Что изменено вручную:**

  * Создан `db.json` с 6 записями запусков (разные статусы, агенты, репозитории и ветки).
  * Добавлен npm-скрипт `mock` для запуска `json-server --watch db.json --port 3001`.
  * Добавлена задержка `setTimeout(700ms)` для имитации сетевого запроса и корректного отображения skeleton-загрузки.
  * Реализована обработка ошибок: `try/catch` с выводом в консоль при недоступности API.

## [2026-11-27] — Оптимизация фильтрации через useMemo

* **Режим Copilot:** Chat
* **Контекст (файлы):** `src/App.tsx`
* **Промпт / Задача:**
  > `filteredRuns` пересчитывается при каждом рендере. Для 6 записей — не проблема, но при росте данных стоит обернуть в `useMemo`.

### Что сгенерировал Copilot
Предложил обернуть вычисление `filteredRuns` в `useMemo` с зависимостями `[runs, statusFilter, normalizedQuery]`, чтобы фильтрация пересчитывалась только при изменении этих значений, а не при каждом рендере компонента. Также рекомендовал добавить импорт `useMemo` из `react`.

### Ручные правки и проверка
* **Статус:** Доработано
* **Что изменено вручную:**
  * Добавлен импорт `useMemo` в `import { useCallback, useEffect, useMemo, useState } from "react"`.
  * Вычисление `filteredRuns` обернуто в `useMemo` с явным массивом зависимостей `[runs, statusFilter, normalizedQuery]`.
  * Функция фильтрации сохранена без изменений — логика отбора по статусу и поисковому запросу не затрагнута.
* **Тестирование:** Production-сборка `npm run build` пройдена.
